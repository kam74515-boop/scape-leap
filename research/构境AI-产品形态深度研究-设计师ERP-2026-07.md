# 构境AI · Formscape —— 产品形态深度研究：设计师 / 设计工作室 ERP

> 版本：v1.0 · 2026-07-23  
> 定位前提（创始人原话）：**「本质上这是一个 AI ERP 系统」**；面向**设计师群体与设计师工作室**，而非 C 端一键出图工具。  
> 本文回答：什么叫「空间设计行业的 ERP」？全球已有哪些形态？中国缺什么？构境 AI 应如何改产品形态、模块边界与优先级？

---

## 0. 一句话结论

**构境 AI 的正确产品形态，不是「ChatGPT + 画布的 AI 出图工具」，而是「设计师工作室的经营 + 设计生产一体化操作系统（Studio OS / Design ERP）」。**

- **骨架**：以**项目**为中心对象的 ERP（客户 → 合同/设计费 → 设计生产七阶段 → 清单/采购 → 施工协同 → 回款/利润）。  
- **肌肉**：AI 赋能层（档案、检索、白模、渲染、选材、报价草稿）——可关掉，系统仍完整。  
- **皮肤**：中性克制的项目管理 UI（看板/表格/表单/甘特/portal），**Codex/ChatGPT 只借视觉语言，不借信息架构**。  
- **错位**：海外 Studio Designer / Programa 做「经营与 FF&E 规格」很深，但几乎不做 AI 设计生产；国内酷家乐/飞流/天猫做「出图与供应链」很强，但**不站在设计师工作室经营侧**。**构境的窗口 = 中国设计师工作室的「经营 ERP × 设计生产 AI」中间层。**

---

## 1. 为什么必须叫 ERP，而不是「AI 设计工具」

### 1.1 设计师工作室的真实经营对象（ERP 视角）

一个 3–30 人的室内/软装工作室，日常运转的**确定性对象**是：

| 经营对象 | 典型形态（今天） | 痛点 |
|---|---|---|
| 客户 / 商机 | 微信好友、Excel、口头 | 线索丢、跟进无记录 |
| 项目 | 文件夹 + 群聊 | 多项目并行失控 |
| 设计流程 | 经验节点，无系统 | 改需求无版本、无上下游联动 |
| 设计资产 | 网盘/U 盘/微信文件 | 版本混乱、交付不可追溯 |
| 清单 / FF&E | Excel | 规格不一致、改一处漏多处 |
| 报价 / 设计费 / 工程费 | Word+Excel | 设计费难被看见；变更难计价 |
| 采购 / 到货 | 微信问厂家 | 交期不可见 |
| 施工协同 | 群聊 + 现场 | 变更无留痕 |
| 回款 / 利润 | 老板脑内 + 会计表 | 不知单项目是否赚钱 |
| 人力 | 谁有空靠吼 | 负荷不均、加班黑洞 |

**这些才是 ERP 的主表。** AI 出图只是「设计生产」子域里的一条流水线。若产品以对话/出图为中心，工作室仍要在 Excel/微信里做真正的经营——工具无法成为「每天打开的系统」。

### 1.2 创始人哲学与 ERP 形态的对齐

> 「不是让设计完全 AI 化，而是优化整个设计行业的价值：让设计师的价值真正在设计中体现……设计费的价值远高于材料。」

落到 ERP：

1. **设计费与设计劳动必须成为一等公民**：报价里独立成块、变更可计价、档案可展示「为什么这样设计」。  
2. **材料/SKU 是附属资源**，不是交易主场（区别于天猫设计家/飞流商城）。  
3. **AI 减负重复劳动，不剥夺决策权**——每个 AI 产出必有可编辑表单与用户确认点。

### 1.3 「AI ERP」的准确定义（避免概念膨胀）

| 是 | 不是 |
|---|---|
| 以项目/流程/资源/财务/执行为主干的管理系统 | 通用财务 ERP（金蝶/用友全量替代） |
| AI 贯穿各模块的**草稿与加速层** | 聊天驱动的 Agent 产品（对话为主列） |
| 设计生产（意向/白模/渲染/清单）与经营（费/人/客）同库 | 纯出图 SaaS 或纯 PM 工具拼装 |
| 站在设计师/工作室立场的轻协同 | 重履约、控货、担保分账的装企平台 |

**最小完备 ERP 模块集（构境应承诺的「系统完整性」）：**

```
CRM/客户  →  项目  →  设计生产流水线  →  规格与清单  →  报价与设计费
                ↓              ↓              ↓
             任务/人力      文件/版本      施工节点/变更
                ↓              ↓              ↓
             利润看板  ←  回款/账单  ←  采购跟踪（可选，轻）
```

## 2. 全球对标：设计师工作室软件的四条产品路线

### 2.1 路线 A —— 财务 + 采购重型「行业 ERP」（美式室内事务所）

| 产品 | 定位 | 强项 | 弱项 | 价位锚（公开信息） |
|---|---|---|---|---|
| **Studio Designer** | Interior design business platform | 项目明细、采购、总账级财务、利润 | 几乎无 AI 设计生产；重、学习成本高 | 约 $72/user/mo 量级 |
| **Design Manager** | Spec + Purchasing + Finance | 项目利润、采购、定金/账单、行业报表 | 同上；偏住宅事务所 | 企业报价为主 |

**启示：** 成熟事务所愿意为「不漏利润、采购不乱」付高价。**「项目行项目（item-based）+ 利润」是硬需求**，构境中期要进规格行与设计费/工程费分账，而不是只做阶段勾选。

### 2.2 路线 B —— 规格 / FF&E / 客户门户（现代 Studio OS）

| 产品 | 定位 | 强项 | 弱项 | 价位锚 |
|---|---|---|---|---|
| **Programa** | Studio management + Specs | FF&E schedule、产品库、客户 Dashboard、一链共享 | 3D/出图弱；偏规格 | ~$47–59/user/mo |
| **DesignFiles / Mydoma / Planify** | 中小工作室 all-in-one | 提案、moodboard、客户协作、部分账单 | 各国碎片化；中国本地化弱 | 数十美元/席/月 |

**启示：** 工作室真正每天点的是：**规格表、选品状态、客户确认链接**。构境现有「材料/家具清单」应对齐 **Schedule（分空间、分品类、状态机：意向→确认→下单→到货）**，并补 **业主只读门户（Client Portal）**。

### 2.3 路线 C —— 事务所经营（时间 / 负荷 / 开票）

| 产品 | 定位 | 强项 | 适用 |
|---|---|---|---|
| **Monograph** | A&E firm management | 线索、预算、工时、开票、预测 | 5–50 人建筑/工程所 |
| **Function Point** | 创意代理经营 | 资源、利润、流程 | 广告/创意所 |

**启示：** 2 人工作室可弱化工时；**8 人以上必须有「人天负荷 + 项目利润」**，否则 AI 再强也解决不了「谁有空做深化」。

### 2.4 路线 D —— AI 叠加经营（2025–2026 新趋势）

| 产品 | 形态 | 信号 |
|---|---|---|
| **Knowlix** 等 | CRM + 项目 + 账单 + AI 队友（问「哪些项目逾期/哪些发票超 30 天」） | AI 先吃**后台运营**，不是先吃建模 |
| **Dzylo** 等 | 报价模板 + 供应商 + 客户沟通 | 垂直「装企/室内业务」AI PM |

**启示：** 国际新玩家的 AI 入口是 **「运营问答 + 草稿」**，与构境「行内 ✦ + drawer」同构；**不要做成首页大聊天**。

### 2.5 中国格局（相对空白）

| 层级 | 代表 | 与工作室 ERP 的关系 |
|---|---|---|
| 设计工具 | 酷家乐、三维家 | 出图/建模强，**经营与设计费弱** |
| 全链路装企 | 天猫设计家、飞流 | 供应链+履约，**立场是交付/工厂** |
| 通用协作 | 飞书/企微/Excel/网盘 | 工作室实际 OS，**无行业对象模型** |
| 装企 ERP | 各类家装 ERP | 偏整装公司工地与材料，**不适配独立设计工作室** |

**中国几乎没有「Programa × 酷家乐生产环节」的合并体。** 这是构境的主战场定义。

## 3. 用户分层与产品形态选择

### 3.1 三类用户（决定模块开关）

| 角色 | 规模 | 核心要什么 | 可砍模块 |
|---|---|---|---|
| **独立设计师** | 1–2 人 | 项目档案、意向/渲染、清单报价、业主确认、设计费账单 | 复杂权限、工时、多组织 |
| **设计工作室** | 3–15 人 | 多项目看板、阶段与任务、成员、规格共享、利润粗看 | 总账级财务 |
| **设计公司** | 15–50 人 | 角色权限、负荷、多项目利润、标准流程模板、客户门户 | 初期可不上深度采购会计 |

**MVP 必须同时覆盖「独立设计师 + 工作室」**；公司级权限/负荷放在第二期。  
**C 端业主不是主账号形态**，而是 **项目内 Client Portal 访客**（确认方案、看报价、验收留痕）。

### 3.2 产品形态选择（推荐）

| 候选形态 | 评价 | 结论 |
|---|---|---|
| A. AI 对话工作台（Chat 主列） | 与创始人否定方向冲突；难承载 ERP 对象 | ❌ 否决 |
| B. 纯项目管理（Asana 皮肤） | 无设计生产与清单行业语义 | ❌ 过薄 |
| C. 纯出图工具（酷家乐子集） | 红海；设计费不可见 | ❌ 否决 |
| D. **Studio OS：项目看板 + 项目内流水线 + 经营侧栏 + AI drawer** | 与 v2.1 IA 一致，可演进 ERP | ✅ **定稿形态** |
| E. 重财务 ERP | 研发重、与设计生产脱节 | ⏳ 第三期可选对接金蝶/用友 |

**定稿：D —— 「空间设计 Studio OS / AI ERP」**  
首页经营看板；进项目后左侧对象导航（流程+协作）；主区业务对象；右侧 AI 赋能。

## 4. 产品形态调整：从「七阶段 Demo」到「工作室 ERP」

### 4.1 现有 Demo 已具备（保留）

- 项目看板 + KPI 摘要  
- 七阶段设计流水线（需求→风格→建模→渲染→选材→采买→施工）  
- 文件 / 任务  
- 透明报价、变更留痕叙事  
- AI drawer + 行内 ✦  
- 意向画布、白模、UI 原子层  

### 4.2 形态缺口（相对真实工作室 ERP）

| 缺口 | 为何关键 | 建议优先级 |
|---|---|---|
| **客户 / 商机（CRM）** | 项目从哪来？独立于项目的客户主数据 | P0（轻量即可） |
| **合同与设计费账单** | 兑现「设计费被看见」；阶段收款 | P0 |
| **角色与权限** | 主案 / 深化 / 软装 / 助理 / 业主访客 | P0 |
| **规格 Schedule 状态机** | 清单从「推荐列表」变成可执行业务 | P0 |
| **业主 Client Portal** | 减少微信传图；确认可留痕 | P0 |
| **项目利润粗看板** | 设计费 − 外协 − 采购差额 | P1 |
| **人力负荷（简单）** | 任务工时或「占用百分比」 | P1 |
| **线索漏斗** | 工作室增长 | P1 |
| **采购 PO / 物流** | 重运营，易滑向天猫战场 | P2，保持轻 |
| **总账 / 税务** | 不自建，对接 | P3 |

### 4.3 推荐信息架构（v2.3 形态）

```
┌─ 工作室空间（Org）─────────────────────────────────────┐
│  首页：经营看板（项目/回款/任务/风险）                      │
│  客户：客户库 + 商机（可选）                                │
│  项目：卡片墙 / 列表 / 甘特（多项目）                       │
│  资源：材料库 / 家具库 / 灵感库（工作室私有）               │
│  财务：设计费账单 / 回款（轻）                              │
│  成员：角色与负荷                                           │
└────────────────────────────────────────────────────────────┘
项目内
├── 概览（进度、预算、利润粗算、风险）
├── 客户与合同（设计费条款、收款节点）
├── 设计流程（七阶段，状态机 + 版本）
├── 规格与清单（Schedule：材料+家具+状态）
├── 报价（设计费块 + 工程/材料块，可对比）
├── 施工协同（节点、验收、变更）
├── 文件 / 任务
├── 共享：生成业主 Portal 链接
└── ✦ AI（drawer，全模块草稿）
```

**相对 v2.1 的关键形态变化：**

1. 增加 **Org 级导航**（不只「项目内」）。  
2. **报价拆成「设计费」与「工程/材料」两块**，首页 KPI 增加「待收设计费」。  
3. **选材+采买合并为 Schedule 视图**（仍可分 Tab），状态驱动，而非两个平行货架。  
4. **业主不进主 App 当用户**，只进 Portal。  
5. AI **永不作为一级导航**。

### 4.4 核心页面形态说明（工作室视角）

1. **经营看板（工作室首页）**  
   - KPI：在手项目、本月设计费应收/已收、延期风险、待客户确认项。  
   - 列表/卡片：按负责人、阶段、利润健康度筛选。  

2. **项目概览**  
   - 上：阶段进度环 + 设计费进度 + 材料预算进度。  
   - 中：「设计价值」叙事卡（设计费 vs 材料占比）——产品哲学 UI 化。  
   - 下：待办、变更、最近资产。  

3. **Schedule（规格中枢）**  
   - 行项目：空间 / 品类 / 名称 / 规格 / 数量 / 单价 / 状态 / 供应商 / 关联效果图。  
   - 状态：`意向 | 比选中 | 已确认 | 已下单 | 已到货 | 变更中`。  
   - AI：以图搜货、替代 SKU、补全规格字段。  

4. **设计费与报价**  
   - 设计费：计价方式（按面积 / 固定包 / 比例）、阶段拆款、已收/未收。  
   - 工程材料：透明分项；变更自动生成金额影响草稿。  
   - 导出：业主可读 PDF（设计说明 + 费项分离）。  

5. **Client Portal**  
   - 只读：阶段成果、待确认清单、报价、验收。  
   - 动作：确认 / 驳回+批注 / 在线确认设计费节点。

## 5. 与竞品的形态错位矩阵

| 能力 | 酷家乐 | 飞流/天猫 | Studio Designer | Programa | **构境 AI（目标）** |
|---|---|---|---|---|---|
| 3D/出图 | 强 | 强 | 弱 | 弱 | 中强（白模+渲染+检索） |
| 项目经营 | 弱 | 弱（偏履约） | 强 | 中 | **强（目标）** |
| 设计费可见 | 弱 | 弱 | 中（财务） | 中 | **强（叙事+账单）** |
| FF&E 规格 | 中 | 商城向 | 强 | 强 | **强（Schedule）** |
| 客户门户 | 弱 | C 端 App | 中 | 强 | **强（轻 Portal）** |
| AI 生产 | 中 | 强 | 弱 | 弱 | **强（赋能层）** |
| 供应链履约 | 中 | **极强** | 采购向 | 弱 | **不做重履约** |
| 中国本地 | 是 | 是 | 否 | 否 | **是** |
| 立场 | 工具/商家 | 交付/工厂 | 事务所财务 | 工作室规格 | **设计师/工作室** |

**可对外讲的差异化一句话：**  
> 给中国设计师工作室的 AI ERP：把设计生产、规格清单、设计费与客户确认收进同一系统；AI 写草稿，人做主；不碰重履约。

## 6. 商业形态（随产品形态调整）

| 层 | 形态 | 说明 |
|---|---|---|
| 席位订阅 | 设计师 / 工作室按席 | 对标酷家乐年费 + 国际 $40–70/席/月心智；国内建议 **¥99–299/席/月** 梯度试探 |
| 工作室包 | 5 席起包年 | 降低小工作室决策成本 |
| 项目插件 | C 端 Portal / 业主只读 | 可按项目加购存储或渲染额度 |
| 交易 | 联盟分佣（中期） | 清单跳转购买，不自建商城 |
| 不做 | 担保分账、派工、自营供应链 | 留给巨头 |

**付费点必须贴「经营结果」**：多项目不乱、设计费好收、清单可执行、客户确认留痕——而不是「多送几次出图」。

## 7. 实施路线（形态落地，不重复写技术栈）

### Phase 0（已完成基线）
- Demo：七阶段 + 看板 + AI drawer + 报价叙事 + UI 原子化 + 意向画布  

### Phase 1 —— **Studio ERP 骨架**（下一阶段主线）
1. Org：工作室 / 成员 / 角色（主案、成员、只读）  
2. 客户主数据 + 项目归属  
3. 设计费模块（条款 + 收款节点状态）  
4. Schedule 统一清单状态机（合并选材/采买交互）  
5. 业主 Portal（只读+确认）  
6. 经营看板 KPI 改为「项目 + 设计费 + 风险」  

### Phase 2 —— **经营加深 + AI 加深**
- 项目利润粗算、负荷、线索  
- 检索式风格库规模化、视口渲染插件  
- 变更自动计价闭环  

### Phase 3 —— **连接**
- 联盟 SKU、轻采购状态  
- 会计软件对接（可选）  
- 开放 API

## 9. 风险与反模式（形态层面）

1. **再度滑向 Chat 主列** —— 任何「首页是对话框」的提案默认否决。  
2. **做成装企工地 ERP** —— 班组、 hump 材料仓、工人派单不是工作室主业。  
3. **做成第二个酷家乐** —— 3D 深度军备竞赛必败；白模+检索+渲染够用即停。  
4. **过早重财务** —— 总账/进销存会拖死团队；先设计费与项目利润粗算。  
5. **AI 自动推进阶段** —— 流程权必须在人；AI 只草稿。
