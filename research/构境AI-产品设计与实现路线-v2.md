## 0. 设计原则（贯穿全文）

1. **增强而非替代。** 创始人哲学："我的目的不是让设计完全 AI 化，而是优化整个设计行业的价值：让设计师的价值真正在设计中体现，让人们知道设计费的价值远高于材料，设计的价值能带来更好的生活。我设计的不是产品，而是生活。" 落到产品上即三条：
   - AI 承担重复劳动（检索、白模、渲染、清单、比价），设计师保留所有审美与方案决策权——每个 AI 产出都必须有"用户决策点"（见第 2 章）；
   - 产品的每个付费点都服务于"让设计劳动被看见、被计价"（透明报价、变更留痕、项目档案），而非把设计压缩成一键出图；
   - C 端体验的最终目标是让业主理解"设计费的价值"——方案背后的故事、材料背后的选择，而非免费效果图。
2. **项目制而非会话制。** 一切资产（对话、意向图、白模、渲染、清单、报价）归属项目，可回溯、可复用。
3. **检索优先，生成兜底。** 能用真实案例与真实 SKU 解决的，不用纯生成（调研报告 §3.3：工具内检索式风格库是空白）。
4. **只做轻与连接，不碰重履约。** 第一年不碰供应链履约与资金担保（调研报告 §0 结论 6、§8 风险）。

## 1. 产品定位与差异化

### 1.1 定位：设计师 / 设计工作室的 AI ERP（Studio OS）

**创始人定调（原话）："本质上这是一个 AI ERP 系统。"**

构境AI 不是聊天工具，不是出图工具，而是**面向设计师群体与设计师工作室（3–50 人为主）的 Studio OS / 经营管理系统**：以**工作室（Org）+ 项目**为中心，把客户、项目管理、设计生产流水线、规格清单（Schedule）、设计费与报价、施工轻协同、协作六类能力装进一个系统；**AI 是贯穿各模块的赋能层，不是产品主角**——它让填表变少、让检索变快、让报价变透明，但系统的骨架是确定性的管理对象与流程，而非对话。

**业主不是主账号用户**，而是项目内 **Client Portal 访客**（确认方案、看报价、验收留痕）。C 端流量叙事保留，但不决定信息架构。

国际对标错位（详见形态研究 §2、§5）：Studio Designer / Design Manager 深财务采购但无 AI 生产；Programa 深 FF&E 与客户门户但无中国本地与 AI 出图；酷家乐/飞流/天猫强工具或供应链但**不站在工作室经营与设计费立场**。构境吃中间层：**经营 ERP × 设计生产 AI × 设计费可见 × 中国本地**。

### 1.2 ERP 模块映射（v2.3）

| ERP 模块 | 构境AI 对应能力 | AI 赋能点 |
|---|---|---|
| 客户 / 商机 | 客户主数据、轻量商机（可选）、项目归属 | 咨询纪要→客户档案草稿 |
| 项目管理 | **工作室经营看板**、项目概览、多项目 KPI、风险 | 概览摘要、延期/预算风险提示 |
| 流程管理 | 七阶段 pipeline、节点状态机、手动推进与回跳 | 阶段产出辅助、"上游有更新"差异提示 |
| 设计生产 | 需求档案、风格检索、白模、渲染、意向画布 | 全流程草稿生成（可编辑） |
| 资源 / 规格 | **Schedule（材料+家具统一状态机）**、工作室私有灵感/SKU 库 | 材质→SKU、以图搜货、规格字段补全 |
| 财务（轻） | **设计费条款与收款节点**、透明工程/材料报价、变更计价、利润粗算 | 清单算量、变更影响汇总、账单草稿 |
| 执行 | 施工节点、验收清单、变更留痕 | 节点计划/验收清单草稿 |
| 协作 | 文件、任务、**角色权限**、**业主 Portal** | 协作数据默认无 AI 自动改写（可信优先） |
| 对外表达 | **汇报 PPT**（业主/内部/交底模板） | 大纲与口播草稿、页标题、素材灌版 |

### 1.3 差异化逻辑（依据调研报告）

- **避开巨头主场。** 天猫设计家（10 万 SKU 供应链 + 履约 + 支付宝担保分账）与飞流AI（65 秒 3 套方案 + 施工图 + 免费）已经把"C 端一键出图 + 重供应链履约"占住（调研报告 §3.1）。构境AI 在任何一层都不与它们正面比价：它们服务"超级个体交付者"（工长/拎包商）并控货控钱；我们服务"专业设计生产者"并开放连接（调研报告 §6）。
- **吃工作流整合空白。** 设计师今天在 SU / PS / 酷家乐 / Excel / 微信之间切换，工具割裂、素材与真实商品脱节、项目管理靠微信（调研报告 §5.2）。单点能力都已验证，但项目制的经营管理整合没人做好——ERP 形态正是对这堆割裂工具（Excel 报价、微信沟通、散落文件）的系统性替代，这是最大机会（调研报告 §7 机会窗口 1）。
- **检索式风格意向是被忽视的差异化点。** 生成式工具"千人一面"，Pinterest/小红书有检索但不是设计工具；"检索真实案例 → 提取风格参数 → 应用到白模"的闭环没人做（调研报告 §3.3、§7 机会窗口 2）。
- **SU/Rhino 只读视觉顾问。** 避开 computer use 可靠性陷阱（OSWorld 约 60-65%，开放桌面任务约 12%，调研报告 §4.1 ③c），做"AI 看着视口给建议/规范检查/出渲染"，差异化空白（调研报告 §7 机会窗口 3）。
- **报价与选材透明化工具（轻量版行业透明化）。** 做天猫的反面：轻、开放、站在设计师立场（调研报告 §7 机会窗口 4）。

### 1.4 用户与商业模式总纲

- **主用户：独立设计师 + 设计工作室（3–15 人核心，15–50 可扩展）**（形态研究 §3）。
- **B 端席位订阅为基本盘**（高频、可订阅；酷家乐付费心智 + 国际 Studio OS $40–70/席/月）：设计师/工作室 ERP 订阅；可提供工作室包年。
- **业主 = Portal 访客**，不以 C 端订阅为收入假设；可按项目加购渲染额度/存储。
- **中期：开放家居生态库 + 联盟分佣**（不自建商城）。
- **远期：施工协同轻工具**（只做连接与透明，不碰履约与资金担保）。
- **付费点贴经营结果**（多项目不乱、设计费好收、清单可执行、确认留痕），而非"多送几次出图"。

### 1.5 否定方向记录（明确不做什么）

- **不是聊天驱动的 AI agent 产品。** v2.0 的"对话为主列 + 画布"骨架作废。对话只是 AI 助手 drawer 内的一种交互方式，不构成产品信息架构；系统的中心是项目、阶段、资产、清单、报价这些确定性管理对象。
- **Codex / ChatGPT 桌面版仅作视觉语言参考**（轻、薄、中性灰黑白、细边框、大留白、等宽数字），**版式不参考它们**——信息架构与页面形态按 ERP / 项目管理产品的自有形态设计（看板、表格、表单、甘特、drawer）。
- 不把"AI 对话"当作首页或默认视图；AI 永远以「✦ AI 助手」drawer 与工作区内行内 ✦ 动作的形态出现，可被收起而不影响任何管理功能的完整使用。
- **不做装企重履约 ERP**（派工、工人、担保分账、自营供应链）——那是天猫主场。
- **不自建总账级财务**——设计费与项目利润粗算即可，深度会计后期对接。

## 2. 信息架构与七阶段工作流

### 2.1 信息架构总览（v2.3：Studio OS = Org 经营 + 项目 ERP，AI 为赋能层）

```
工作室空间（Org）
├── 经营看板：在手项目 / 设计费应收已收 / 延期风险 / 待客户确认
├── 客户库（+ 可选商机）
├── 项目墙 / 列表
├── 资源库（材料 / 家具 / 灵感·工作室私有）
├── 财务轻（设计费账单）
└── 成员与角色
项目内（Project）
├── 左侧导航：概览 / 客户与合同 / 需求 / 风格 / 意向画布 / 建模 / 渲染
│            / 规格清单 Schedule / 报价 / 施工 / 文件 / 任务 / 汇报 PPT / 共享 Portal
├── 主区：对象工作区全宽（表单、画布、视口、Schedule 表、报价、甘特）
└── 右侧：✦ AI drawer（可关；关后管理功能完整）
```

> v2.1 的「首页=项目看板」保留为默认落地页；v2.3 将其升级为**工作室经营看板**，并增加 Org 级客户/成员/财务入口。选材+采买在导航上可仍分项，数据层统一为 **Schedule 状态机**（形态研究 §4.3）。

- **工作对象是主角，AI 是辅助。** 每个阶段工作区承载该阶段的确定性管理对象（表单/资产/表格），AI 产出（如需求档案、节点计划、报价草稿）一律以**可手动编辑的表单与卡片**呈现——AI 填草稿，人改定稿，修改不经过对话。
- **AI 的两个触点**：① 右侧全局「✦ AI 助手」drawer（对话、追问、跨阶段任务，自动带入当前阶段上下文）；② 工作区内**行内 ✦ 动作**（字段级的"AI 补全/换一版/生成说明"按钮）。两者之外不出现对话界面。
- **文件与任务是纯管理功能，无 AI**：上传/预览/版本、任务分派/状态/截止日期，不做 AI 摘要与智能推荐，保证协作数据的确定性与可信度。
- 阶段**非严格线性**：允许回跳（改需求 → 重出方案）；每个阶段产出一个"确认态"资产，由用户**手动推进**阶段状态，回跳时下游资产标记"已过期"并提示重生成——流程管理权在用户，AI 不自动流转阶段。
- 七阶段对应调研报告六环节拆解（§1），其中"空间建模"拆为"建模 + 渲染"两阶段。

### 2.2 逐阶段定义（输入 / 输出 / AI 介入点 / 用户决策点）

**阶段 1：需求分析 —— 对话采集、表单定稿的需求档案**

- 输入：用户自然语言描述（家庭结构、预算、户型、生活习惯、硬约束，在 ✦ AI 助手 drawer 中对话采集，或直接手填表单）；可上传户型图/照片。
- 输出：**结构化需求档案**（JSON Schema：房型、面积、预算区间、风格倾向关键词、功能需求清单、禁忌项、时间计划），以**可手动编辑的表单/卡片**呈现在阶段工作区，存为项目元数据，全程被下游阶段引用。
- AI 介入点：LLM 多轮对话追问补全缺口（"厨房开放还是封闭？""是否有老人/儿童？"），并将对话结果抽取填入表单草稿；表单内每个字段带行内 ✦"AI 建议"动作。
- 用户决策点：档案确认页逐条可改（改表单，不改对话）；预算与风格关键词直接驱动后续检索与报价参数。
- 边界：不做"替用户做决定"的推荐强推，AI 只给选项与取舍说明。

**阶段 2：风格意向检索 —— 检索优先而非纯生成**

- 输入：需求档案中的风格关键词 + 用户任选参考图（上传或从库中选）。
- 输出：**风格意向板（Moodboard）**：3-5 组风格方向，每组含检索到的真实案例图、色板、材质关键词、风格参数（明度/饱和度/材质占比）。
- AI 介入点：CLIP/SigLIP 图文向量检索授权图库与用户私有灵感库；LLM 为每组方向生成"设计语言描述"（为什么适合该需求）。
- 用户决策点：选定 1 个主方向（可多选混合，AI 提示冲突点）；可锁定单张图作为"风格锚点"供渲染阶段使用。
- 差异化说明：这是调研报告 §3.3 指出的空白——工具内检索式风格库。真实案例自带落地参照，避免生成式"千人一面"。

**阶段 3：平面图 → 3D 白模**

- 输入：户型图（手绘/拍照/PDF/CAD 截图均可）+ 需求档案中的功能需求。
- 输出：**可编辑 3D 白模**（three.js 视口）：墙体/门窗/房间分区几何体 + 布局建议（家具摆位灰块）。
- AI 介入点：多模态 VLM 识别户型图 → 结构化房间数据 → 规则几何重建；LLM 依据需求档案给出布局调整建议（"书房与主卧对调更安静"）。
- 用户决策点：白模内直接拖拽改墙/调布局；AI 建议以"可一键应用/忽略"的卡片呈现。
- **产品边界声明（必须内置在 UI）**：白模精度够做可视化与布局决策，不够做施工依据——"施工尺寸以实测为准"（调研报告 §4.1 ③a，MeltFlex 同类口径）。

**阶段 4：AI 渲染 —— 视口截图 + 预设技能**

- 输入：白模视口截图（或 SU/Rhino 插件截图）+ 阶段 2 的风格锚点 + 预设技能选择。
- 输出：**保结构渲染图**（img2img，几何强度可调），多方案对比视图；可回溯的参数记录（模型、强度、种子、提示词）。
- AI 介入点：SD/FLUX + ControlNet 管线；六个预设技能（见 §4.4）；LLM 辅助写提示词（把风格参数翻译为 prompt）。
- 用户决策点：选技能 → 调强度滑杆 → 出图 → 择优；每次生成最多并行 4 张供挑选，避免无限重抽。
- 同时覆盖 SU/Rhino 用户：桌面插件上传视口截图 → 同一渲染管线（Veras 模式，调研报告 §4.1 ③b）。

**阶段 5：材料选材 —— 材质 → 真实 SKU**

- 输入：渲染图中的材质区域（用户点选或 AI 分割）+ 预算约束。
- 输出：**材质替换清单**：每种材质匹配 2-3 个真实可购 SKU（品牌、价格、环保等级、效果图预览）。
- AI 介入点：视觉 embedding 检索（CLIP 图像向量）做"材质 → SKU"匹配；LLM 生成选材说明（为什么这个价位/等级的材料适合该方案）。
- 用户决策点：逐材质确认或换选；锁定后写入报价清单。
- 边界：SKU 数据来自联盟与品牌官方库，不自建重资产库（调研报告 §8 风险）。

**阶段 6：家具采买 —— 可购买生态库**

- 输入：白模空间尺寸 + 风格参数 + 预算余额。
- 输出：**家具配置清单**：按空间分组的 SKU 推荐（含 3D 预览位、价格、库存状态、购买链接），合计与预算对比。
- AI 介入点：尺寸约束过滤（放得下）+ 风格向量匹配（搭得上）+ 以图搜货（效果图中的家具 → 相似可购款）。
- 用户决策点：替换/删除单品；导出清单或直接跳转购买（联盟链接）。
- 原则：开放生态库（多平台比价），不做封闭商城——与天猫/飞流的自有商城错位（调研报告 §3.3）。

**阶段 7：施工落地 —— 轻量项目管理 + 透明报价**

- 输入：确认后的需求档案 + 白模 + 选材/家具清单。
- 输出：**施工项目空间**：透明报价表（SKU 级，分项单价可比对）、施工时间线（节点计划）、验收清单、变更留痕列表。
- AI 介入点：规则引擎算量 + LLM 生成节点计划与验收清单草稿；变更时 LLM 自动汇总影响（"换这款地板：总价 +¥1,240，工期不变"）。
- 用户决策点：设计师与业主双方确认报价；每次变更双方留痕确认。
- **边界：只做工具与透明，不碰履约、派单、资金担保**（那是天猫烧钱的主场，调研报告 §0/§8）。报价输出标注"辅助参考，以实际合同为准"。

### 2.3 阶段状态与回流规则

- 每阶段三态：`未开始 / 进行中 / 已确认`。确认后资产进入"基准版"，回跳修改产生新版本，旧版本保留在阶段工作区的资产历史中。
- 跨阶段依赖可视化：左侧项目导航的七阶段上，下游阶段显示"上游有更新"徽标，一键触发差异重算；阶段推进由用户手动确认，不自动流转。

### 2.4 汇报 PPT（v2.4 新增正式功能）

**定位：** 设计师工作室的**对外表达层**——把项目内已确认资产（需求档案、风格锚点、效果图、清单、报价）组装成可讲可发的汇报稿，而不是另起一个 PPT 软件。

| 项 | 说明 |
|---|---|
| 入口 | 项目内「管理 → 汇报 PPT」；概览页快捷入口 |
| 模板 | 业主汇报 / 内部评审 / 施工交底 |
| 结构 | 左幻灯片列表（可勾选页）· 中预览 · 右模板与素材清单 |
| 自动灌入 | 需求档案、意向板/画布锚点、渲染结果、选材家具、报价摘要 |
| AI | 大纲、页标题、过渡句、30 秒口播稿（drawer + 行内 ✦） |
| 导出 | pptx / PDF（演示态先做流程与 UI；正式版接 pptx 引擎） |
| 比例 | 16:9 默认；可选 4:3 |
| 边界 | 不做完整 Office 排版器；**素材源 = 本项目**，避免空 PPT |

与设计哲学对齐：PPT 是「让设计劳动被看见」的交付物之一——封面与报价页突出设计决策叙事，而非仅堆材料清单。

## 3. 界面设计规范（版式为 ERP/项目管理产品自有形态；ChatGPT 与 Codex 仅作视觉语言参考）

### 3.1 总体布局

两级页面结构，桌面优先：

**第一级：项目看板首页（欢迎页）**

- 顶部 KPI 摘要条：进行中项目数 / 预算总额（等宽数字）/ 待办任务数 / 本月动态（新建项目、阶段推进、变更条数），一屏掌握经营概况；
- 项目卡片墙：卡片含项目缩略图（最近渲染图或白模截图）、项目名、当前阶段徽标、预算进度条、负责人头像、更新时间；按更新时间排序，支持筛选（阶段/负责人）与搜索；
- 主按钮：新建项目；
- 这是产品的默认首页与欢迎页——不存在对话式欢迎页。

**第二级：项目内三列（管理对象为主，AI 为辅）**

- **左侧项目导航（220px，固定，浅色细边框）**：概览 / 需求 / 风格 / 建模 / 渲染 / 选材 / 采买 / 施工（七阶段各带状态徽标）/ 文件 / 任务；底部：成员、插件中心（SU/Rhino 插件下载与连接状态）、设置。
- **主区：阶段工作区（全宽）**：工作对象是主角——需求档案表单、风格意向板、3D 白模视口（three.js）、渲染对比视图、选材/采买清单表格、透明报价表、施工时间线；概览页为项目仪表盘（阶段进度环、预算 vs 已采、近期变更、待办任务）。
- **右侧：✦ AI 助手 drawer（可开合，默认收起为 48px 边栏，展开 360px）**：全局常驻、跟随当前阶段上下文（在建模页打开即带入白模与需求档案）；内含对话流 + 底部输入框（`@` 技能、图片上传、随阶段变化的技能快捷 chips）；**收起后全部管理功能完整可用**。
- 响应式：< 1280px 时 AI drawer 变为全屏覆盖层；< 768px 单列（阶段工作区为主，导航收纳为抽屉，AI 助手全屏切换）。

### 3.2 视觉语言（v2.4 与 Pen / Demo 令牌统一）

| Token | 浅色 | 用途 |
|---|---|---|
| `bg` | `#FFFFFF` | 主区 |
| `bg-sidebar` / `bg-subtle` | `#F7F7F8` / `#F1F1F2` | 侧栏与次级底 |
| `text` / `text2` / `text3` | `#0D0D0D` / `#5D5D5D` / `#9B9B9B` | 正文 / 次级 / 辅助 |
| `border` | `#00000014` | 1px 细边框 |
| `ai` / `ai-edge` | `#8B5CF6` / `#C4B5FD` | AI 触点、画布选中与连线 |
| `ok` / `warn` / `cyan` / `orange` | 绿/琥珀/青/橙 | 状态，非主按钮 |
| 主按钮 | 近黑底白字 | **主操作永远黑白**，不与 AI 紫抢主操作 |

- **主题**：浅色默认 + 深色模式。
- **分隔**：1px 细线；禁用重阴影，卡片仅用边框 + 极浅投影。
- **圆角**：卡片 12–14px；按钮 9–12px；chip 全圆角。
- **字体**：UI `Noto Sans SC` / 系统栈；数字与价格用 `JetBrains Mono`。
- **字号**：基准 15px；辅助 12–13px；标题 16–24px 半粗。
- **色彩策略**：界面低饱和；**效果图 / 材质 / 意向图才是彩色主角**；紫仅 AI 层。

### 3.3 核心组件定义

1. **项目卡片与 KPI 摘要条**：
   - 项目卡片：缩略图（最近渲染图/白模截图，加载前浅灰骨架）、项目名、当前阶段徽标、预算进度条（等宽数字：已采/预算）、负责人头像、更新时间；hover 浮现快捷操作（打开/复制链接/归档）。
   - KPI 摘要条：四格指标（进行中项目 / 预算总额 / 待办任务 / 本月动态），数字全等宽大号，点击下钻到对应筛选视图。
2. **✦ AI 助手 drawer**：
   - 头部：✦ 图标 + 当前上下文标签（如"上下文：阶段 3 · 建模"），展开/收起/全屏控件；收起态为 48px 边栏，仅 ✦ 图标与未读提示点。
   - 消息流（drawer 内部件）：AI 消息左置头像 + 纯文本/Markdown，无气泡底色，可内嵌资产卡片；用户消息右置浅底圆角气泡（浅色模式 `#f4f4f4`）；系统事件（阶段确认、资产生成完成）居中灰字小字带等宽时间戳。
   - 底部输入框：圆角 16px，自适应 1-8 行，Enter 发送 / Shift+Enter 换行；支持 `@` 唤起技能、图片拖拽/粘贴、随阶段变化的技能快捷 chips（渲染阶段显示"风格迁移 / 材质替换 / 局部重绘 / 日夜景"）。
   - drawer 内 AI 产出落地规则：凡生成管理对象（档案、清单、报价、计划），以"写入工作区"按钮收尾，写入后即为可手动编辑的表单/表格，而非留在对话里。
3. **行内 ✦ 动作与阶段导航**：
   - 行内 ✦ 动作：工作区内字段/卡片级 AI 按钮（档案字段的"AI 建议"、报价行的"换低价替代"、时间线节点的"生成验收清单"）；图标统一 ✦，触发结果就地填充并可再编辑，不跳转、不弹对话。
   - 阶段导航：左侧项目导航中的七阶段列表即 stepper——当前阶段实心强调，已确认打勾，"上游有更新"显示橙色圆点徽标；点击切换阶段工作区；阶段推进按钮（"确认并进入下一阶段"）位于工作区底部，手动触发。
4. **风格卡片**：
   - 封面：检索到的真实案例图（加载前为按风格主色生成的渐变占位图，避免灰块）；
   - 下方：五色色板（点击复制色值）+ 风格标签 chips + 匹配度说明一行字；
   - 操作：设为风格锚点 / 查看相似 / 加入意向板。
5. **SKU 卡片**：
   - 商品图、名称、价格（等宽大字）、环保等级徽标（E0/E1/ENF）、库存状态；
   - 比价条：同款/相似款跨平台最低价提示；
   - 操作：替换当前材质位 / 加入清单 / 跳转购买（外链，联盟标识）。
6. **透明报价表**：
   - 分组表格（空间 → 项目 → SKU），列：名称 / 规格 / 数量 / 单价 / 小计 / 市场参考价 / 差异；
   - 数字全等宽右对齐；高于市场价的行橙色标注；表尾合计 + 预算对比进度条；
   - 每行可展开查看依据（来源链接、用量计算说明）。
7. **施工时间线**：
   - 横向甘特 + 节点卡片（拆除/水电/泥木/油漆/安装/验收），节点含计划日期、责任人、验收清单入口；
   - 延期节点红色描边并自动级联提示后续影响。
8. **变更留痕列表**：
   - 倒序列表，每条含：时间（等宽）、变更内容摘要、金额/工期影响（+/− 等宽）、双方确认状态；
   - 导出 PDF 作为合同附件。

### 3.4 交互与易用度

- **新手引导**：首次进入落在项目看板首页，3 步引导（新建项目 → 填需求档案 → 出第一张渲染），10 分钟内产出第一个可视化成果（"第一张图"是最关键的激活时刻）；引导可随时跳过，项目导航保留"继续引导"入口。
- **每阶段"下一步建议"**：阶段完成后，✦ AI 助手 drawer 自动弹出 1-3 个下一步快捷按钮（如选材完成后："生成报价表 / 继续调整材质 / 进入施工计划"），同时工作区底部常驻手动推进按钮——AI 建议、人做决定，降低"接下来该干嘛"的认知成本。
- **空状态**：项目看板空时给模板项目一键创建 + KPI 条占位说明；阶段工作区空时显示该阶段示例资产 + 一句话指引（"上传一张户型图，AI 可帮你建白模"），指引旁配行内 ✦ 动作入口。
- **键盘快捷键**：⌘K 全局搜索（项目/资产/任务/技能命令）；⌘N 新建项目；⌘B 项目导航开合；⌘J AI 助手 drawer 开合；drawer 聚焦时 Enter 发送 / Shift+Enter 换行；Esc 关闭浮层。快捷键表在 ⌘K 面板底部常驻可查。
- **加载与流式反馈**：drawer 内文本 SSE 流式输出（打字机）；图像生成在**工作区内**显示进度骨架 + 预计秒数 + 当前步骤（"结构提取 → 风格迁移 → 细节增强"），完成后直接落入工作区资产区；白模重建显示步骤进度条。所有长任务可取消。
- **错误兜底**：生成失败自动降级（换备选模型/降分辨率）并明示；网络中断保留表单草稿与已生成资产；任何 AI 输出失败都给"重试 / 换方案 / 人工反馈"三个出口，不出现死胡同；AI 不可用时管理功能（表单、清单、报价、文件、任务）不受任何影响。
- **移动端适配原则**：移动端只读 + 轻操作（看板、概览、确认、批注、选 SKU），不做建模与渲染操作；AI 助手全屏化；C 端业主的主要触点（确认方案、查看报价、验收留痕）必须移动端可用。

## 4. 全流程 AI 化方案与开源技术选型

> 每环节给出：AI 任务 / 推荐开源方案 / 备选 / 成熟度风险（评级沿用调研报告 §4.1：🟢 成熟 / 🟡 有缺陷 / 🔴 不成熟）。

### 4.1 需求分析：LLM 多轮对话 + 结构化抽取 🟢

- AI 任务：多轮追问补全需求 → 按 JSON Schema 抽取结构化需求档案 → 档案变更的增量更新。
- 推荐：**Qwen3**（中文场景与 function calling 友好）或 **Llama-3.x**，推理层 **vLLM**（服务端高并发）或 **Ollama**（本地/单机部署）；结构化输出用 JSON Schema 约束解码 + function calling。
- 备选：云端合规 API（OpenAI 兼容接口的国内合规模型）走同一 Provider 抽象层。
- 风险：低。注意档案 Schema 版本化，避免存量项目档案无法迁移。

### 4.2 风格意向检索：图文向量 + 向量库 🟢

- AI 任务：文本/图片 → 风格向量 → 检索真实案例；风格参数提取（色板、材质关键词）。
- 推荐：**CLIP / SigLIP** 图文 embedding + **Qdrant**（生产）或 **FAISS**（单机/demo）；色板提取用 k-means 色彩聚类（传统算法即可，不必上模型）。
- 备选：Jina-CLIP / 中文优化的 Chinese-CLIP。
- 风险：算法零障碍，**风险全部在图源版权**（调研报告 §4.2 结论 1）。策略三层：① 授权图库/内容平台合作；② 用户私有灵感库（用户上传，仅自己可检索，默认不入公共库）；③ 公共库只做索引与跳转，不明示转售图片。

### 4.3 平面图 → 3D 白模：VLM 识别 + 规则几何重建 🟢

- AI 任务：户型图（手绘/拍照/PDF）→ 墙体/门窗/房间结构识别 → 参数化几何重建 → three.js 白模。
- 推荐：**Qwen2.5-VL** 等多模态 VLM 做结构识别（输出结构化房间数据），**规则引擎做几何重建**（识别结果 → 参数化建模，不用生成式 3D）；训练/微调数据用开源数据集 **CubiCasa5k**、**RPLAN**。
- 备选：CubiCasa 类专用分割模型（房间/墙体分割 + 矢量化后处理）。
- 风险：🟢 成熟（5 家以上商用，调研报告 §4.1 ③a），不构成壁垒，价值在"把项目锚定在工作台"。**边界必须写进产品：可视化与布局决策可用，施工以实测为准。**

### 4.4 AI 渲染：SD/FLUX + ControlNet + ComfyUI 🟢

- AI 任务：白模/SU 视口截图 → 保结构风格渲染（img2img，几何强度可调）。
- 推荐：**Stable Diffusion / FLUX + ControlNet**（深度/线稿/分割条件保结构）+ **ComfyUI** 管线编排（服务端工作流 API 化）。
- 六个预设技能（对应调研报告 §9 阶段一"预设技能包"）：

  | 技能 | 管线要点 |
  |---|---|
  | 风格迁移 | ControlNet（depth）+ 风格 LoRA / 风格锚点图 IP-Adapter |
  | 材质替换 | 分割选区 + inpainting，保留光照 |
  | 局部重绘 | 涂抹蒙版 + inpainting |
  | 意向版生成 | 多图检索 + 排版模板（检索优先，生成补位） |
  | 日夜景切换 | 光照条件 ControlNet + 色彩迁移 |
  | 线稿上色 | ControlNet（lineart）+ 色板约束 |

- 备选：云端图像 API（合规渠道）作为峰值溢出与低端算力用户的降级链路。
- 风险：生成可控性靠 ControlNet 强度参数暴露给用户（"结构保持"滑杆）。
- **算力来源与合规红线**：主链路 = 云端合规 API / 自部署 GPU 推理；**本机 ChatGPT 反代生图仅作为"高级用户自带算力"的隐藏 hack——违反 OpenAI ToS、有封号风险、稳定性不可控，不做任何官方宣传与默认入口，商业模式不得建立在之上**（调研报告 §4.2 结论 4、§8 风险）。

### 4.5 材质识别 → SKU 匹配 🟡

- AI 任务：渲染图/实拍图中的材质区域 → 视觉 embedding → 检索真实 SKU 库；以图搜货。
- 推荐：CLIP 图像向量检索（与 §4.2 共用向量基础设施，SKU 图独立 collection）；区域分割用 SAM 类开源分割模型辅助用户点选。
- 备选：商品级匹配接平台联盟 API 自带的以图搜图能力。
- 风险：🟡 "材质 → 真实可买 SKU"的映射质量依赖 SKU 库数据规模与标注（调研报告 §4.1 ④）；对策是接联盟与品牌官方库，并允许用户手动纠错（纠错数据回流优化匹配）。

### 4.6 报价与施工计划：规则引擎 + LLM 🟡

- AI 任务：清单算量报价、节点计划生成、验收清单生成、变更影响汇总。
- 推荐：**规则引擎做数字**（算量、单价、合计——确定性计算，不让 LLM 算账），**LLM 做文案与结构**（节点计划草稿、验收清单、变更说明）；工艺与节点模板库人工维护起步。
- 备选：报价参数化模板（Excel 兼容导入，承接设计师现有报价习惯）。
- 风险：🟡 报价准确性责任——产品边界"辅助参考，以实际合同与实测为准"必须内置在每一份输出物上（调研报告 §8）。

### 4.7 SU/Rhino 集成：只做"只读视觉顾问" 🔴→🟢（按定义收窄）

- 明确不做：**AI 自动操作 SU/Rhino 建模（GUI Agent）**——2026 年不可靠：OSWorld 基准成功率约 60-65%，开放式桌面任务可靠性仅约 12%（调研报告 §4.1 ③c、§10.1）。作为远期叙事，不写入任何对外承诺。
- 明确做（只读视觉，可靠性要求低，🟢）：
  1. 视口截图 → AI 渲染（Veras 模式，§4.4 管线复用）；
  2. 视口截图 → 设计建议 / 规范检查（VLM 看图说话："此处过道净宽约 800mm，低于常用舒适值"）；
  3. 截图 → 风格意向匹配（接 §4.2 检索）。
- 形态：SU/Rhino 轻量插件（截图上传 + 结果回显面板），不做模型写回。注意 SketchUp 2026 已原生内置 AI Render（调研报告 §3.2），插件窗口在收窄，SU 侧重"建议/规范检查"差异化，Rhino 侧重建筑/室内垂直用户群。

### 4.8 整体 AI 架构

```
前端 (React) ──SSE──> 后端 (Rust axum)
                          │
                    AI Provider 抽象层（OpenAI 兼容接口）
                    ┌─────┼──────────┬───────────┐
                 Ollama  vLLM 集群  云端合规API   ComfyUI(图像)
                (本地)   (自部署)   (主链路之一)  (渲染管线)
                          │
                    任务队列（异步生成任务：渲染/重建/批量检索）
```

- **Provider 抽象层**：所有文本模型经 OpenAI 兼容接口调用，Ollama / vLLM / 云端 API 可插拔切换（配置级，不改代码）；图像任务走独立 ComfyUI 工作流接口。
- **任务队列**：渲染、白模重建等长任务入队异步执行，前端轮询/SSE 推送进度；支持取消与优先级（交互式操作优先）。
- **流式 SSE**：文本逐 token 推送；图像任务推送阶段进度事件。
- **成本护栏**：按项目/租户配额计数，渲染任务记消耗（模型、分辨率、时长，等宽数字展示给用户），订阅梯度对应配额（见 §6）。

## 5. 技术架构与实现路线

### 5.1 技术栈

- **前端**：Vite + React + TypeScript；three.js（白模/3D 视口）；SSE 客户端流式渲染；组件样式遵循 §3.2 视觉规范（CSS 变量实现双主题）。
- **后端**：Rust + axum——托管前端 dist 静态资源 + REST API + AI Provider 代理（转发 SSE 流）；demo 期单体即可。
- **数据层**：
  - Demo 期：内存态（进程内 HashMap + JSON 快照落盘），零依赖启动；
  - 生产：**PostgreSQL**（项目/档案/清单/报价/用户）+ **Qdrant**（风格图与 SKU 向量）+ **MinIO**（图片/模型/导出文件对象存储）。
- **插件**：SU/Rhino 截图插件（各自原生 API 开发，后端走同一 REST API）。

### 5.1.1 核心数据模型（简表）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| User | id, role(设计师/业主), plan(订阅档), quota | 双端共用一套账户，角色决定默认视图 |
| Project | id, owner_id, stage, status, created_at | 最小管理单元；stage 为七阶段状态机 |
| RequirementProfile | project_id, schema_version, json | 结构化需求档案，Schema 版本化（§4.1 风险） |
| Asset | id, project_id, stage, type, version, uri | 阶段资产（意向板/白模/渲染/清单/报价），版本化保留历史 |
| StyleAnchor | project_id, image_id, palette, params | 风格锚点：锚点图 + 色板 + 风格参数 |
| SKU | id, source(联盟/品牌), price, eco_grade, vector_id, updated_at | 真实商品；向量存 Qdrant，文件存 MinIO |
| Quote / ChangeLog | project_id, items[], status, confirmed_by | 报价与变更留痕，双方确认状态机 |
| Task | id, type(渲染/重建/检索), payload, progress, cost | 异步任务队列记录，成本护栏计量依据 |

### 5.1.2 接口分层

- REST API 分四层：`/projects`（项目、看板与阶段状态）、`/assistant`（AI 助手对话与 SSE 流）、`/assets`（阶段资产 CRUD 与版本）、`/ai`（任务提交/进度/取消，经 Provider 抽象层转发）。
- 前后端同仓：axum 直接托管前端 `dist/`，demo 期单二进制交付，降低设计师用户的部署门槛（本地可跑 Ollama 全离线链路）。

### 5.2 分阶段实施路线（对应调研报告 §9 三阶段）

**阶段一（0-6 个月）MVP：设计师 AI ERP 骨架**

- 交付物：
  1. ERP 骨架壳（项目看板首页含 KPI 条 + 项目内三列：项目导航/全宽阶段工作区/✦ AI 助手 drawer，项目制，七阶段状态机）；
  2. 阶段 1 需求档案（可编辑表单 + AI 对话采集 + JSON Schema 抽取 + 确认页）；
  3. 阶段 3 白模（VLM 识别 + 规则重建 + three.js 可编辑视口）；
  4. 阶段 2 风格检索（用户私有灵感库先行 + 首批授权图源）；
  5. 阶段 4 渲染（截图上传入口 + 六个预设技能中的前四个：风格迁移/材质替换/局部重绘/意向版）；
  6. Provider 抽象层 + 任务队列 + SSE。
- 验收标准：
  - 新建项目 → 需求档案确认 → 上传户型图出白模 → 选定风格 → 出第一张保结构渲染图，全流程 ≤ 15 分钟；
  - 渲染结构保持度：ControlNet 高强度档下墙体/门窗位置无漂移（抽样人工评审通过率 ≥ 90%）；
  - 1000 名活跃设计师试用，验证 399-999 元/年订阅意愿（调研报告 §9 阶段一目标）。

**阶段二（6-12 个月）：闭环到真实商品**

- 交付物：
  1. 阶段 5 选材（材质点选 → SKU 匹配 → 替换清单）；
  2. 阶段 6 采买（开放生态库：联盟 SKU + 品牌 3D 模型合作，以图搜货，比价条）；
  3. C 端轻应用/小程序：业主看方案、确认、按项目付费解锁；
  4. SU/Rhino 插件 v1（截图渲染 + 只读建议）；
  5. 数据层切换 PostgreSQL + Qdrant + MinIO。
- 验收标准：
  - 渲染图 → 可购买清单转化率可度量（清单导出/跳转购买埋点）；
  - SKU 匹配 Top-3 人工评审命中率 ≥ 70%，用户纠错回流闭环；
  - C 端单项目解锁付费跑通（支付、交付、售后边界）。

**阶段三（12-24 个月）：透明化与协同**

- 交付物：
  1. 阶段 7 施工空间（透明报价表、时间线、验收清单、变更留痕、PDF 导出）；
  2. 报价比价与透明模板市场；
  3. B 端团队版/设计公司版（多成员、项目权限、品牌模板）；
  4. 数据飞轮：项目数据 → 风格/报价/布局模型微调 → 反哺工作台。
- 验收标准：
  - 报价表从清单生成 ≤ 1 分钟，每行可追溯依据；
  - 变更留痕双方确认流程闭环，导出件可作为合同附件；
  - 团队版付费验证（设计公司 ≥ 50 家）。

## 6. 商业闭环与指标

### 6.1 定价（对标酷家乐 399-3000 元/年，调研报告 §5.1/§5.3）

| 档位 | 价格（元/年/人） | 权益要点 |
|---|---|---|
| 免费版 | 0 | 1 个项目、基础渲染配额、水印导出——获客与体验 |
| 专业版 | 399 | 项目数放开、标准渲染配额、风格检索库、白模编辑 |
| 高级版 | 999 | 高渲染配额、预设技能全开、SU/Rhino 插件、选材采买闭环 |
| 团队版 | 2000 | 多人协作、品牌模板、报价协同、管理后台 |

- **C 端**：免费浏览与基础体验；**按项目解锁**（单个装修项目数十至数百元解锁全流程：高清渲染、清单、报价、施工协同），契合低频属性（调研报告 §5.2）。
- **联盟分佣**（中期）：家具/材料经联盟链接成交抽佣，不自建商城、不压库存（调研报告 §5.3 第 3 条）。
- 变现路径遵循"工具费 → 项目解锁 → 交易分佣"的梯度，回答"怎么从工具费走到交易抽成"（调研报告 §2.2 核心判断）。

### 6.2 核心指标

- **北极星指标：月活跃设计项目数**（而非注册用户数）——同时反映 B 端粘性与 C 端转化（调研报告 §9）。
- 过程指标：首张渲染产出时长（激活）、阶段确认完成率（分阶段漏斗）、渲染→清单转化率、订阅续费率、C 端项目解锁率、变更留痕使用率（施工协同粘性）。
- 财务护栏：单项目 AI 算力成本 vs 订阅/解锁收入的毛利监控，渲染配额即成本控制阀。

## 7. 风险与边界（对应调研报告 §8，逐条给产品侧对策）

| 风险（调研报告 §8） | 等级 | 产品侧对策 |
|---|---|---|
| 巨头降维（天猫/字节/群核跟进工作台形态） | 高 | 抢 12-18 个月速度窗口；深耕项目制工作流数据（档案、模板、留痕）形成迁移成本；不做巨头可一夜复制的单点功能 |
| C 端低频留存崩塌 | 高 | 不以 C 端订阅为收入假设；按项目解锁 + 项目内交易变现；C 端定位为 B 端设计师的交付触点 |
| 反代 ChatGPT 生图合规与封号 | 中高 | 仅作隐藏 hack，无默认入口、无宣传；主链路走云端合规 API/自部署模型（§4.4）；用户协议中明示该功能风险自负 |
| SKU 生态库数据成本（3D 建模、价格库存同步） | 中高 | 接联盟与品牌官方库，不自建重资产库；SKU 卡片标注数据更新时间；以图搜货用平台既有能力兜底 |
| 版权（风格图库、生成图权属） | 中 | 三层图源策略（授权库/用户私有库/索引跳转，§4.2）；生成图明示授权条款；检索结果保留来源署名 |
| 施工图/报价准确性责任 | 中 | 产品边界声明内置 UI 与输出物："白模与报价为辅助参考，施工以实测与正式合同为准"（§2.2 阶段 3/7）；不提供施工图纸资质类承诺 |
| 双端冷启动鸡生蛋 | 中 | 先 B 端设计师（高频付费）→ 设计师带 C 端业主进场看方案/确认/解锁（§5.2 阶段二 C 端轻应用） |
| 资本市场对工具估值冷淡（群核镜像） | 中 | 融资叙事讲"工作台 → 交易入口 → 数据飞轮"，不讲纯工具（调研报告 §2.3 启示③） |

### 7.1 三条产品红线（再强调）

1. 第一年不碰重供应链与施工履约、不做资金担保（巨头主场）。
2. 不承诺"AI 全自动建模"（GUI Agent 2026 年不可靠，调研报告 §4.1 ③c）。
3. 商业模式不建立在反代 hack 之上（合规红线）。
